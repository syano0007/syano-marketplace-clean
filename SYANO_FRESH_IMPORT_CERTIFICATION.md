## PHASE 7 — RECOVERY HARDENING

Issues found and fixed:

### Fix 1: `generate-manifest.ts` — enum counts were hardcoded
**Problem:** `project.manifest.json` had stale enum counts (notification_type=32, delivery_mission_status=9) that didn't match the live DB (33 and 10 respectively).
**Fix:** Updated `scripts/src/generate-manifest.ts` to query live enum counts via `pg_enum` + `pg_type` and write them to the manifest.
**Verification:** `pnpm manifest:generate` now outputs `notification_type=33 order_status=15 delivery_mission_status=10`.

### Fix 2: `AGENT_BOOTSTRAP.md` — extra artifact workflows not documented
**Problem:** A fresh agent seeing `artifacts/api-server: API Server` as FAILED could interpret this as the API Server being down, causing them to create duplicate workflows.
**Fix:** Added `⚠️ EXTRA SYSTEM WORKFLOWS` section at the very top of AGENT_BOOTSTRAP.md (before QUICK START), documenting all 3 extra artifact workflows with their causes and the clear instruction to ignore them.

### Known non-issues (documented, no action needed):
| Issue | Reason no fix needed |
|---|---|
| `artifacts/api-server: API Server` still FAILING | Intentional: this workflow lacks `PORT=8080`; the official `API Server` workflow owns port 8080. Adding a PORT default would cause silent duplicate startup. |
| `artifacts/mockup-sandbox: Component Preview Server` still FAILING | Port 8081 is owned by Mobile Expo. Mockup sandbox is a dev-only tool, not one of the 4 official services. |
| RESEND_API_KEY not set | Optional email service. Intentionally absent in dev. |
| Mobile returns `HTTP 000` on curl | Metro bundler does not speak standard HTTP. Correct behavior. |
